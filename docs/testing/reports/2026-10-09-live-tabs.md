# Live Tabs per-extension OFF — 9 October 2026

Scope: approved backend-only compatibility correction. Chrome, Firefox and Safari package bytes remain unchanged. No schema migration, provider configuration change or production Redis mutation was used during development.

## Cause and correction

The extension's local switch calls `POST /live/settings`. Its old backend handler interpreted every caller as the website's account-wide switch: OFF changed the shared enabled flag and purged all devices. Sibling extensions then received disabled responses. This behavior also existed at the Clerk checkpoint; it was not introduced by the Supabase promotion.

The existing online Supabase verifier, OAuth client classifier and active-account lookup now retain the verified session ID and extension capability on the request. Extension OFF uses that identity to atomically stop publication, delete only its snapshot/index entry and emit its device-delete event. Siblings and account opt-in remain active. Explicit own ON increments the admission generation, re-arms that session and retains existing account opt-in behavior. Website/native first-party settings retain their account-wide OFF/purge semantics. Existing cross-session authorization remains enforced; device IDs and body labels never confer ownership. Stopping preserves independent new-window and window-name preferences; Forget retains its previous cleanup behavior.

Every extension snapshot commit (changed full push, identical/no-op push, heartbeat and encryption migration) checks the account flag, own stop state and captured generation in the same Redis Lua operation that writes and publishes. OFF therefore cannot be undone by a previously admitted push. An obsolete request completing after explicit ON is acknowledged with 200 but does not write or publish; replying disabled would incorrectly make the unchanged extension turn its renewed local switch OFF. Current OFF still returns the established 403 disabled response.
