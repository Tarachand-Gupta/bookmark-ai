# @bookmark-ai/docs

The public documentation site — [docs.bookmark-ai.cloud](https://docs.bookmark-ai.cloud).
[Docusaurus](https://docusaurus.io/) 3, docs-only mode (`routeBasePath: '/'`, so the
docs *are* the site). The sidebar is autogenerated from the folder structure:
numbered filename prefixes set the order, `_category_.json` names the groups, and
each page's `slug:` is explicit so files can be renumbered without breaking links.

## Local development

```bash
pnpm --filter @bookmark-ai/docs start     # dev server on :3000
pnpm --filter @bookmark-ai/docs build     # production build into build/
pnpm --filter @bookmark-ai/docs check-types
```

`onBrokenLinks` is set to **throw**, so a bad internal link fails the build
rather than shipping a 404. That's deliberate — fix the link.

## The demo animations

The animated demos on pages like [Search](docs/guides/04-search.mdx) and
[Live sessions](docs/guides/07-live-sessions.mdx) are **the same components the
marketing landing page and the in-app onboarding tour render** — they are
imported from `@bookmark-ai/ui/demos/*`, not copied. Change one and every surface
changes together.

Those components are written in Tailwind utility classes and Docusaurus has no
Tailwind pipeline, so rather than adding one site-wide:

- `src/css/demos.src.css` is a small Tailwind input that scans **only**
  `packages/ui/src/demos` and pulls in the shared brand tokens from
  `@bookmark-ai/ui/theme.css`;
- `scripts/build-demo-css.mjs` compiles it to `src/css/demos.css` (generated,
  gitignored) with the Tailwind CLI. Both `start` and `build` run it first, so a
  fresh clone and a Vercel build both work with no committed artifact;
- `src/components/Demo.tsx` frames an animation and scopes those utilities to it
  via a `bmk-demo` class.

Read the comment block at the top of `demos.src.css` before changing any of it —
there are three non-obvious constraints (no preflight, unlayered utilities, and a
zero-specificity scoped reset) that exist so Tailwind and Infima can coexist
without either one flattening the other.

Every demo gates its own motion behind `prefers-reduced-motion` and is authored to
settle on its final frame, so reduced-motion visitors and pre-hydration HTML get
a complete picture rather than a frozen half-state.

## Deployment

Deployed with the Vercel CLI to the **`bookmark-ai-docs`** project
(`prj_2HY8gb2jUe7AjAC9P5t3PbwdqTtZ`), aliased to `docs.bookmark-ai.cloud`. It is
**not** Git-connected — pushing to `main` deploys nothing here.

**Deploy from the repository root**, not from this directory:

```bash
cd /path/to/bookmark-ai
vercel deploy --prod
```

The project's Root Directory is `apps/docs`, so the whole monorepo is uploaded and
the build runs in here. That's required, not incidental: this package depends on
`@bookmark-ai/ui` through the pnpm workspace, and a `workspace:*` dependency can't
resolve if only `apps/docs` is uploaded. Install is filtered to
`pnpm install --filter @bookmark-ai/docs...` so the rest of the monorepo isn't
installed. The root `.vercelignore` keeps build caches, generated mobile projects
and all `.env*` files out of the upload.
